# Capcraft v1.2 개발

Windows / Python 3.12 / PyQt6 WebEngine + Fabric.js 기반 캡처 편집기입니다.
사용 중인 v1.1 배포본은 `dist/`에 유지합니다. 현재 소스의 최종 배포 빌드는 보류 중입니다.
`dist-dev/`에 남아 있는 중간 검증 빌드는 최신 팝아웃 개선을 포함하지 않습니다.

## 실행과 검증

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci --ignore-scripts --omit=optional
npm run vendor
.\.venv\Scripts\python.exe main.py
```

`vendor/`는 로컬 라이브러리·이모티콘 데이터와 라이선스를 포함합니다. 앱 실행 시 CDN이 필요하지 않습니다.
개발 의존성 설치에는 네트워크가 필요합니다. 브라우저 테스트용 Chrome이 없다면
`npx puppeteer browsers install chrome`으로 설치합니다.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
npm test
.\.venv\Scripts\python.exe tests/qt_smoke.py
```

Qt 테스트는 사용자 설정과 기록을 임시 폴더로 격리합니다. 결과는 `test-results/`에 저장됩니다.
빌드 승인을 받은 후에만 `build.bat`을 실행합니다. 출력은 `dist-dev/`이며 기존 `dist/`는 삭제하지 않습니다.
설치 프로그램은 `installer_v1.2.iss`를 별도 Inno Setup으로 컴파일합니다.

## 이번 개선

- 한글 저장 경로 전달, 설정·최근 기록의 원자적 저장, 전송 중단 시 기존 기록 보존.
- 서로 다른 캡처의 최근 기록 중복 판정과 비동기 저장 순서 수정.
- 혼합 DPI/음수 좌표 모니터 캡처 계산, 캡처 오버레이 정리, 초기 화면이 그대로인 스크롤 캡처 처리.
- 선/화살표 첫 이동, 연결 글상자 반전·복원, 펜 배경 투명도 복원, JSON 배경·크기 보존.
- 강제 합성 레이어 반복 갱신 제거, 개체 캐시와 렌더 요청 조정, Qt의 강제 GPU 옵션 정리.
- jsPDF 업데이트, SVG 출력 정화, 라이브러리와 이모티콘 데이터 로컬화.
- 일회성 개발 자료는 삭제하지 않고 `archive/legacy/`로 이동. `node_modules/`는 Git 추적만 해제.

## 팝아웃 화질

`popout-quality.js`가 화면 복사 대신 원본 이미지와 벡터에서 최대 4배 밀도로 스냅샷을 생성합니다.
기울기는 스트립을 두 번 확대하던 방식 대신 단일 역투영으로 처리하고, 표시 크기와 내부 픽셀 크기를 분리했습니다.
개체 확대가 끝나면 필요한 해상도로 재생성합니다. 이동 중에는 이미 생성한 이미지를 사용합니다.
개별 작업 표면은 약 4백만 픽셀로 제한되며, 큰 영역에서는 배율이 낮아집니다.

새 팝아웃의 선명도 기본값은 35입니다. 팝아웃 도구막대에서 0~100으로 조절하고, 0이면 선명화를 끕니다.
기본 설정에서도 변경할 수 있습니다. 작은 반경의 휘도 언샤프 마스크를 사용하고, 임계값과 보정량 상한으로
균일 영역의 잡음·테두리 번짐을 억제합니다. 원본은 수정하지 않으며 저장·실행 취소에 설정을 포함합니다.
기존 기록은 선명도 0으로 호환되며, 옛 팝아웃의 저해상도 스냅샷을 고해상도 원본으로 복구할 수는 없습니다.
새 렌더링의 이점을 모두 얻으려면 팝아웃을 새로 생성하세요.

ClearType 탈색·CLAHE·AI 초해상화는 색상·문자 형태 변경과 추가 의존성을 피하기 위해 적용하지 않았습니다.
원본 비트맵에 없는 실제 세부 정보를 복원한다고 보장하지 않습니다.

## 확인 범위와 남은 제한

- 백엔드 11개 테스트 통과: 저장 실패/재시작, 좌표 계산, 캡처 모드, 오버레이 70회, 합성 스크롤 결합.
- 편집 시나리오 26개를 Chrome 및 Qt WebEngine에서 통과. 별도로 JavaScript 오류·외부 요청 검사.
- 도형/이모티콘/이미지/모자이크 표시 경로를 합성 이미지로 구성해 실제 브라우저 포인터 이동·확대를 검사.
  프레임 샘플의 배경 지워짐과 개체 중심 사라짐을 검사하지만, OS 합성기·GPU 화면 출력 자체를 측정하는 것은 아닙니다.
- 실제 다중 모니터 혼합 DPI, 다른 앱의 스크롤 캡처, 사용자 PC에서의 드라이버별 깜빡임은 추가 수동 확인이 필요합니다.
- Fabric 5의 보안 권고가 완전히 해소된 것은 아닙니다. SVG 출력 정화는 완화 조치이며,
  메이저 버전 교체와 호환성 검증은 별도 과제입니다. 신뢰할 수 없는 프로젝트 파일은 열지 마세요.
- `graphify update .`는 현재 환경에 CLI가 없어 수행되지 않았으므로 기존 지식 그래프는 최신 소스와 다를 수 있습니다.

## 반응속도 회귀 수정 (2026-09-16)

- 앱과 Qt 테스트에서 강제 소프트웨어 캔버스 옵션을 제거하고 Chromium의 기본 가속 선택을 사용합니다.
  환경변수 `QTWEBENGINE_CHROMIUM_FLAGS`를 직접 지정했다면 해당 사용자 설정은 유지됩니다. 변경 적용에는 앱 재시작이 필요합니다.
- 팝아웃의 픽셀 결과를 캐시합니다. 이동·외부 회전·그림자 변경에는 재생성하지 않고, 배율/기울기/선명도/마스크가 달라질 때 갱신합니다.
- 팝아웃 PNG 인코딩도 픽셀이 변경될 때만 수행합니다. 기록과 최근 목록에서 동일 JSON을 재사용하며 800ms 뒤의 중복 썸네일 갱신을 제거했습니다.
- 일반 이미지 이동 완료 때마다 필터를 다시 적용하던 처리를 제거했습니다.
- 선명화의 블러는 네이티브 Canvas 필터로 처리하고, 원근 변환의 픽셀별 임시 배열 할당을 제거했습니다.
- 팝아웃 속성 연속 입력은 120ms 동안 묶고 입력 확정 시 즉시 반영합니다. 확정된 픽셀·설정을 기록에 저장합니다.

`node tests/performance.mjs before` / `after`로 동일한 640×360 팝아웃의 생성, 변경 없는 재생성, 위치 변경 후 기록 저장을 측정합니다.
이번 Chrome 측정에서 재생성 5회의 중앙값은 약 62.2ms → 측정 정밀도상 0ms,
기록 저장은 약 20.2ms → 3.5ms였습니다. 새 팝아웃 생성은 약 443ms → 361ms로 여전히 비용이 있고,
변경 후 첫 기록 저장은 약 71ms였습니다. 이 수치는 해당 합성 장면의 결과이지 사용자 PC 전체 반응속도나 FPS 보장이 아닙니다.
큰 팝아웃 생성·기울기 변경은 아직 동기 처리이므로 순간 지연이 남을 수 있습니다. 배포 빌드는 수행하지 않았습니다.

## 다음 클릭까지 화면 갱신이 지연되던 문제 (2026-09-17)

Fabric 5의 `toCanvasElement()`가 내부 `renderCanvas()`를 통해 예약된 본 화면 렌더를 취소하는 문제를 재현했습니다.
최근 목록 썸네일 생성 후에도 기존 화면 갱신 요청을 유지하도록 앱 캔버스의 내보내기 경로를 보완했습니다.
상시 렌더링이나 중복 동기 렌더를 추가하지 않고 필요한 예약만 복구합니다.
회귀 테스트는 추가 클릭 없이 선택·색상·좌우반전이 그려지는지 검사합니다.
실제 브라우저 포인터로 도형·이모티콘·이미지·모자이크의 첫 클릭 선택과 화면 갱신도 확인합니다.

## 최근 목록 전환의 기록 손상·지연 수정 (2026-09-17)

- 로드 중에 활성 항목 번호부터 변경하던 동작을 제거했습니다. 별도 StaticCanvas에서 복원하고 마지막 요청의 준비가 끝난 시점에만 실제 캔버스와 활성 항목을 교체합니다.
- 복원은 하나씩 진행하며 대기 중 클릭은 마지막 요청으로 합칩니다. 취소된 요청은 본 화면을 지우거나 기록을 저장하지 않습니다.
- 전환 중에는 캔버스 편집만 잠시 막고 도구 버튼은 계속 사용할 수 있습니다. 복원 후 도구 선택 상태를 유지합니다.
- 전환·정렬·기록 초기 표시에 따른 불필요한 전체 기록 저장/목록 DOM 재생성을 줄였습니다. 첫 전환에서 배경색 차이를 편집으로 잘못 판단하던 기록 초기화도 수정했습니다.
- 저장된 팝아웃의 최종 이미지를 그대로 표시하며, 로드 때마다 선명화·원근 변환을 다시 계산하지 않습니다. 속성을 바꾸면 다시 생성합니다.
- 썸네일은 click으로 전환하여 삭제 버튼의 mousedown이 먼저 항목을 로드하던 충돌을 제거했습니다.
- 연속 전환의 기록 불변성, 마지막 요청 반영, 현재 항목으로 취소, 새 캡처 우선, 잘못된 JSON 복구, 전환 중 상단/하위 도구 선택 유지를 검사합니다.
- 격리된 Qt 창에서 Computer Use로 썸네일과 도형/타원 버튼의 단일 클릭 반영을 확인했습니다. 사용자 기록 파일은 수정하지 않았습니다.

수동 재현 창: `.\\.venv\\Scripts\\python.exe tests/qt_smoke.py --interactive --recent`.
큰 이미지의 최초 디코딩 비용과 실제 편집 후 전체 기록 저장 비용은 여전히 존재합니다. 모든 PC에서 지연이 없다고 보장하지 않습니다.

## 두 클릭 이전 개체가 표시되던 문제 (2026-09-18)

후속 재현에서 이 절의 저장/썸네일 수정만으로는 증상이 해결되지 않았음을 확인했습니다.
2026-09-19 실제 클릭 로그에서는 클릭 대상, mouse-up 이후 활성 개체, Canvas 그리기 대상이
일치했지만 Qt 창에는 이전 개체와 도구막대가 남았습니다. 이 절의 변경을 최종 원인 해결로
해석해서는 안 됩니다. 화면 합성/표시 경로를 별도로 검증 중입니다.

일반 개체 선택의 `mouse:down` 처리에서 실제 편집이 없는데도 `saveHistory()`를 실행하고 있었습니다.
이 과정이 전체 문서 직렬화와 최근 항목 썸네일 렌더링을 선택 프레임과 같은 입력 시점에 실행하여,
Qt WebEngine에서는 현재 마우스 위치보다 화면의 선택 테두리와 도구 상태가 뒤늦게 표시될 수 있었습니다.

- 일반 클릭에서는 기록 저장을 하지 않습니다. 이동·크기 변경·색상·반전 등 실제 변경 완료 때만 기록합니다.
- 기록 JSON은 즉시 보존하지만 썸네일 렌더링은 입력이 끝난 뒤 250ms로 묶어 한 번만 수행합니다.
- 선택 생성·변경 테두리는 해당 입력 차례에 즉시 그립니다.
- 상단/하위 도구막대와 사이드바의 별도 강제 합성 레이어를 제거했습니다.
- 효과가 없었던 `QSG_RHI_BACKEND=opengl` 강제 설정은 제거하고 Qt 기본 그래픽 경로로 복귀했습니다.

다섯 개 개체의 연속 클릭에서 클릭 ID·내부 선택 ID·실제 렌더 ID가 매번 일치하는 회귀 검사를 추가했습니다.
일반 클릭 중 썸네일 내보내기가 0회인지, 속성 변경 화면이 썸네일보다 먼저 그려지는지도 검사합니다.
Chrome 전체 검사, 백엔드 11개, Qt WebEngine 편집 시나리오 26개와 JavaScript 오류 검사가 통과했습니다.
실행 중인 사용자 창에는 적용되지 않으며 완전히 종료 후 `python main.py`로 재시작해야 합니다.
선택 진단 창: `.\.venv\Scripts\python.exe tests/qt_smoke.py --interactive --selection`.
콘솔의 `SELECTION_TRACE`는 실제 클릭 대상/선택 ID, `SELECTION_PAINT`는 본 캔버스 렌더 시점의 선택 ID입니다.

### 표시 갱신 보완 (2026-09-19)

Qt 연결 시 `presentation-refresh.js`를 설치합니다. 입력 또는 본 캔버스 렌더 후
180ms의 유한한 opacity 애니메이션으로 합성 프레임 갱신을 유도합니다.
상시 애니메이션이나 Fabric 재렌더 루프는 사용하지 않으며 GPU 설정도 변경하지 않습니다.
이는 내부 선택과 실제 표시가 어긋나는 현상에 대한 우회 보완이며 그래픽 드라이버 원인 확정은 아닙니다.
Computer Use로 진단 창의 타원→직사각형→별 단일 클릭 선택 전환을 확인했습니다.
간헐적 재현이 완전히 사라졌는지는 사용자 환경에서 추가 확인이 필요합니다.
`node tests/presentation-refresh.cjs`는 입력 묶기, 유휴 중단, 썸네일 제외를 검사합니다.

### 로컬 OCR

썸네일 왼쪽 아래 회색 OCR 버튼을 누르면 원본 캡처를 인식합니다. 완료된 파란 버튼을
다시 누르면 선택 가능한 텍스트 창과 전체 복사/닫기/다시 인식 버튼이 표시됩니다.
결과는 최근 캡처 기록에 함께 저장됩니다. 빈 배경에는 원본 이미지가 없으므로 실행하지 않습니다.
OCR은 편집 도형·모자이크를 합성한 화면이 아닌 원본 캡처 기준입니다.

- CPU 전용 RapidOCR 3.9.2 / ONNX Runtime 1.30.0, PP-OCRv5 server 검출 + 한글·영문 인식.
- 모델 설치 후 인터넷 불필요. 실행 중 모델 자동 다운로드 금지, ONNX 원격측정 비활성화.
- 입력으로 URL/파일 경로를 받지 않으며 캡처 이미지는 외부로 전송하지 않습니다.
- 처음 누를 때만 모델을 검증·로드합니다. 작업 스레드 1개, CPU 추론 스레드 최대 4개.
- 긴 이미지는 원본 해상도 타일로 처리하고 겹친 결과를 제거합니다.
- 낮은 모델 확신도는 안내하지만 정확성을 보증하는 지표는 아닙니다. 중요한 숫자는 원본 확인이 필요합니다.
- 90/180도 회전 문서, 필기, 복잡한 표·다단 문서의 의미적 읽기 순서는 보장하지 않습니다.
  한글 오회전을 방지하기 위해 자동 180도 분류는 끕니다. 생성형 AI 보정은 사용하지 않습니다.

새 환경 설치(선택한 Python으로 실행):

```powershell
python -m pip install -r requirements-ocr.txt
python scripts/setup_ocr.py
```

설치 스크립트만 공개 모델을 다운로드하며 고정 SHA-256을 검사합니다. 모델 출처는
`models/ocr/manifest.json` 및 `models/ocr/README.md`에 기록했습니다.
현재 개발 PC의 Python 3.13은 프로젝트 `.ocr-deps`를, `.venv` Python 3.12는 해당 환경의
설치된 의존성을 사용합니다. 배포 spec에 모델·OCR UI·추론 런타임을 포함했지만 배포 빌드는 아직 하지 않았습니다.

검증: `python tests/ocr_accuracy.py`는 네트워크를 차단하고 24px 밝은 화면, 16px 다크모드,
12px 작은 글씨의 한글·영문·숫자 샘플을 검사합니다. 현재 샘플의 공백 제외 문자 오류율은 0%였으나
띄어쓰기 오차는 있으며, 모든 캡처에 대한 정확도 보장은 아닙니다.
`python tests/qt_smoke.py --ocr`는 실제 Qt 브리지, UI 응답, 결과창, 복사, 저장을 검사합니다.
